# 设计

Next.js 中心入口 `/center` → 同源 API → 中心 FastAPI → PostgreSQL。

采集机维持原 Python 浏览器服务和调度器，附加 outbound agent。Agent 通过 HTTPS 回传已发布快照并领取只读采集任务。SQLite 暂作为节点缓存与断网补传数据源；PostgreSQL 是中心页面的数据源。不跨网络共享 SQLite 文件。

中心管理员使用随机管理密钥登录，浏览器仅保存加密 HttpOnly 会话；每台节点使用独立随机密钥，数据库仅保存 SHA-256 摘要。中心模式屏蔽原本机连接设置与代理接口。

中心通过节点行锁串行化同一节点的领取与快照更新，任务租约 120 秒，过期领取生成新随机凭证，旧凭证不能提交。快照时间戳防止旧结果覆盖新结果。首次启动从本地 business_cache 补传，收到中心确认后持久化游标。

节点保留调度权，避免两套自动调度重复执行；中心提供手动派发和选定机器的采集策略管理。中心离线不会中断节点按既定频率采集。

发票上传不走自动重试采集任务队列；已有人工确认边界保留。`/agent/tunnel` 是经过节点独立密钥验证的主动 WebSocket 连接。中心按流 ID 复用画面与命令，二进制帧不转换为 base64；浏览器输入和变更命令不自动重放。HTTP 文件接口每批限制 32 MiB。

中心复用原业务页面与筛选/排序/导出逻辑，直接从 PostgreSQL 读取业务快照。运行状态等节点接口按查询缓存到 PostgreSQL，页面优先读缓存，后台通过隧道刷新。新查询尚无运行状态缓存时等待节点首次响应；节点离线返回具体原因。涉及节点配置、窗口、账号、发票上传的操作转发到选定机器，成功后更新中心记录。多机经营数据使用中心全局整数店铺 ID，映射到节点 UUID 与本地 ID。

目前中心 API 使用单进程，隧道连接驻留该进程；不可配置多个 uvicorn workers。需要多副本时必须先引入跨进程连接路由与事件总线。
