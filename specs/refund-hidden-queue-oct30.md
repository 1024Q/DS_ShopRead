# 2026-10-30 自动退款、队列序号与隐藏采集

## 自动退款规则

- 仅在拼多多「重点待办」的售后采集任务内部执行，不新增定时任务或并发名额。
- 重新精确查询售后单，确认原生状态为「退款，拼多多处理中」或「退货退款，拼多多处理中」、状态码 3，且平台仍提供同意退款操作 1001。
- 阈值使用原生 `orderAmount` 整数分，必须大于 0 且小于 10000；不使用申请退款金额代替订单金额。退款金额必须为正且不大于订单金额。
- 原生退款前置检查出现验货、账户异常、余额不足、额外确认或未知风险字段时，交给人工处理。
- 提交使用原生售后单版本号。先以独占创建方式保存财务操作意图并 fsync，再向平台提交。
- 已受理、已拒绝、提交中、响应未知的售后单均不会自动重复提交。超时或重启后不以缺少成功响应为由再次退款。
- 正常列表读取仍通过只读适配器；退款接口限定在独立的 `backend/auto_refunds.py`，不进入只读缓存/接口重放白名单。

## 记录位置与查看

- 节点财务操作记录：`.data/refund-actions/<本机店铺 ID>/<售后单 ID>.json`，不作为数据库运行日志保存，也不受七天日志保留期清理。
- 网页「重点待办中心 → 自动退款记录」按店铺查看最近 100 条。
- 节点鉴权接口：`GET /api/shops/<id>/refund-actions`，支持 `before` 和 `limit`；读取不会唤醒浏览器。
- 中心沿用鉴权代理与快照缓存，重映射店铺 ID；显示「平台已受理」不等同于承诺资金已经结算到账。

## 其他改动

- 同步与数据源移除「今日核心数据覆盖情况」界面，不删除统计和采集数据。
- 排队主任务与子步骤分别使用节点命名空间下的 `/M序号`、`/S序号`，避免跨节点和主子任务序号冲突。队列顺序会随调度变化，不作为永久业务主键。
- 调试模式、自动登录验证、采集页面及导出页面保持隐藏。仅明确的手动显示操作允许可见；远程控制操作不被自动窗口策略打断。
- 新建会话不恢复历史「显示窗口」偏好；自动冷启动清除上一轮会话的临时手动显示状态。
- 实机发现 Chrome 会在部分 CDP 操作后重新显示已隐藏的主窗口，因此隐藏时同时移至整个虚拟桌面之外并去掉任务栏入口。手动显示恢复原位置与样式；服务重启后没有原位置记录时恢复到可见桌面。验收以「显示范围内可见」和「是否抢占前台」为准。
- 自动工作页使用 `Target.createTarget(hidden=true, background=true, focus=false)`；浏览器拥有者 socket 随页面保持连接，关闭后目标自动销毁，不写可见标签的遗留归属记录。手动显示模式仍允许普通工作标签，模式变更会使空闲页面缓存失效。
- 冷启动店铺主页窗口通过 CDP 在创建时指定显示范围之外的初始坐标，避免「创建后再隐藏」的间隙。已用独立临时 Chrome 资料验证初始真实窗口位置，并在真实已登录店铺验证隐藏工作页读取及关闭回收。
- 导出页设置 `requires_native_surface=True`，直接创建离屏窗口，保留失败截图的绘制表面；普通隐藏工作页已验证真实 CDP 输入和下载，离屏导出页已验证真实截图。该模式是按功能选择，不是在错误后回退到桌面可见页面。
